Label check, SWE-bench Multilingual (10 cards: JavaScript, PHP, Ruby)

The rule, in plain words. Each card is one moment when an AI coding agent's edit broke tests that used to pass. The code stays broken until the command listed as the end of the break (or the end of the run). You are asked one thing: during that stretch, did the agent's own log SHOW the break?

Answer "yes, shown" if ANY of these appears in what the agent saw during the stretch:

  1. A command that actually ran tests (for example npm test, jest, phpunit, rspec, rake test, or any command whose output shows tests being run) reported at least one failure or error. Any failing test counts, not only the ones listed as broken.
  2. Any output names one of the broken tests as failing (the test names are listed on the card).
  3. Any output prints the error this break causes: a SyntaxError, PHP "Parse error", Ruby NameError or NoMethodError, "Cannot find module", and so on, pointing at the file the agent had just edited. This includes errors printed by the agent's own scripts or by a compiler, not only by test runs.

Answer "no, not shown" if none of those appears. Typical "not shown" cases: the agent ran no tests at all while the code was broken; it ran tests that all passed; it ran a test command that collected zero tests (printing "0 tests" or no results); its own check script printed success; it only read or listed files. Reading the code does not count, even if a human could spot the bug in it.

Answer "can't tell" only if the card does not contain enough of the log to decide (for example the output was cut off). Do not use it because no error line is printed: that is a "not shown".
